STRUCTURE FIREBASE REALTIME DATABASE
====================================

moteur/
├── live/                          # Données temps réel (écrasées ~1 s)
│   ├── ax                         # Accélération axe X (g) — moyenne fenêtre
│   ├── ay                         # Accélération axe Y (g)
│   ├── az                         # Accélération axe Z (g)
│   ├── a_rms                      # Accélération RMS (m/s²) — GRANDEUR FIABLE
│   ├── vibration_rms              # Vitesse vibratoire estimée (mm/s)
│   ├── rpm                        # Vitesse de rotation (tr/min)
│   ├── rpm_nominal                # Consigne / plaque moteur (tr/min)
│   ├── status                     # NORMAL | SURVEILLANCE | AVERTISSEMENT | ALARME | ARRET
│   ├── alert_level                # Niveau d'alerte affiché
│   ├── diagnostic                 # Message court
│   ├── anomaly_hint               # Hypothèse de cause (non certifiée)
│   ├── timestamp                  # Secondes depuis boot ESP32
│   ├── online                     # true si ESP32 publie
│   ├── unit_a_rms                 # "m/s2"
│   ├── unit_vibration_rms         # "mm/s (estime)"
│   └── note_vibration             # Rappel méthodologique
│
├── config/                        # Seuils éditables depuis l'interface Web
│   ├── rpm_nominal
│   ├── rpm_min
│   ├── rpm_max
│   ├── vib_normal_mms
│   ├── vib_alerte_mms
│   ├── vib_critique_mms
│   ├── a_rms_normal_ms2
│   ├── a_rms_alerte_ms2
│   ├── a_rms_critique_ms2
│   └── note
│
└── historique/                    # Journal (nouvel enfant ~10 s)
    └── <millis>/
        ├── timestamp
        ├── epoch_ms
        ├── vibration_rms
        ├── a_rms
        ├── rpm
        ├── ax
        ├── ay
        ├── az
        ├── status
        └── diagnostic

Règles de sécurité (développement / mémoire — À RENFORCER en production) :

{
  "rules": {
    ".read": true,
    ".write": true
  }
}

Production recommandée (exemple) :
- Auth anonyme ou email pour le dashboard
- Secret / token pour l'ESP32
- Historique avec TTL ou Cloud Function de purge

Limite RTDB pour l'historique :
- Un nœud par mesure toutes les 10 s ≈ 8640 nœuds/jour.
- Au-delà de quelques jours, préférer Firestore, BigQuery, InfluxDB ou export CSV.
